# InstanSeg Architecture and Codebase Analysis

This document provides detailed answers to questions regarding the loss function, embedding creation, instantiation, biological metadata, and augmentation pipelines in the InstanSeg codebase.

---

### 1. Loss Function in U-net InstanSeg
**Why is the loss function file (`instanseg_loss.py`) so large (1,481 lines)?**

The file `instanseg/utils/loss/instanseg_loss.py` is exceptionally large because it serves multiple purposes beyond calculating training losses:
1. **Bundled Inference & Postprocessing:** The file contains the complete postprocessing pipeline (`postprocessing` and `TTA_postprocessing` methods) used during inference to convert raw predictions into instance masks.
2. **Torchscript Deployment Wrapper:** It defines the `InstanSeg_Torchscript` wrapper (a `nn.Module` class), which compiles and packages the entire network alongside its postprocessing logic (and boundary resolution) into a single JIT trace for production.
3. **Internal Helper Operations:** It houses all coordinate mapping, cropping, and clustering utility functions (e.g., `convert`, `find_all_local_maxima`, `torch_peak_local_max`, `centre_crop`, `compute_crops`, `find_connected_components`, `merge_sparse_predictions`, `guide_function`, and `generate_coordinate_map`).
4. **Multiple Feature Engineering Schemes:** It implements several feature engineering variations (`feature_engineering`, `feature_engineering_2`, `feature_engineering_3`, `feature_engineering_10`) to transform the distance/coordinate representations before classification.
5. **Multi-Target Logic:** It supports joint nuclei and cell segmentation (`self.cells_and_nuclei`), which replicates operations, splits prediction channels, and coordinates overlaps.

**Core Loss Function Components:**
The training loss itself is computed via `InstanSeg.forward(prediction, instances)`. It is a compound loss:
- **Seed Loss:** Measures foreground accuracy using BCE (`binary_xloss`) or L1 distance against the computed Euclidean Distance Transform (EDT) map.
- **Instance Loss:** For each true instance centroid, a crop is extracted. Feature engineering computes coordinate offsets (embedding coordinates minus centroid coordinates) scaled by a predicted pixel uncertainty ($\sigma$). A small MLP (`ProbabilityNet` or `ConvProbabilityNet`) predicts a local binary mask within the crop, which is supervised using a binary loss (e.g., Lovasz-Hinge or Dice-Focal loss).

### 2. Simplifying the Loss Function for Cell-Only Segmentation
**Can we reduce the codebase size if we only focus on cell segmentation and deprecate other modes (e.g., nuclei)?**

**Yes, significantly.** We can achieve a reduction of **over 80%** in the size of `instanseg_loss.py` through the following modifications:

* **Decoupling Postprocessing:** Move `postprocessing`, `TTA_postprocessing`, `InstanSeg_Torchscript`, and their geometric helper functions (`convert`, `merge_sparse_predictions`, `torch_peak_local_max`) into a separate `postprocessing.py` module.
* **Removing `cells_and_nuclei` Logic:** Delete all loops iterating over target channels (`iterations = 2`, `dim_out / 2`, etc.) and the cell-nucleus boundary resolution logic (`resolve_cell_and_nucleus_boundaries` imports and calls).
* **Removing Unused Loss Variants:** Eliminate alternative loss configurations in `update_binary_loss` and `update_seed_loss` (such as `cross_entropy`, `dice_loss`, and `general_dice_loss`) that are not used in cell segmentation.

### 3. Embedding Creation and Types
**Which file defines the process of embedding creation, and which functions correspond to each type?**

The raw prediction tensor outputs from the U-Net model are parsed and transformed in **`instanseg/utils/loss/instanseg_loss.py`** (during loss calculation/postprocessing) and generated by the UNet decoder branches in **`instanseg/utils/models/InstanSeg_UNet.py`**.

InstanSeg uses **3 embedding/prediction types** to obtain the final mask:

| Embedding Type | Code Variable | Responsible Parsing logic | Description |
| :--- | :--- | :--- | :--- |
| **Spatial Coordinates / Center Offsets** | `spatial_emb` / `fields` | `prediction_b[:, 0:self.dim_coords]` + coordinate grid `xxyy` | Predicted pixel offsets relative to the coordinate grid. Represents the spatial center vectors mapping each pixel to its instance center. |
| **Pixel-wise Uncertainty/Variance** | `sigma` | `prediction_b[:, self.dim_coords:self.dim_coords + self.n_sigma]` | Represents the size or uncertainty metric ($\sigma$) of the instance, used to scale the relative embedding distance during cropping. |
| **Seed / EDT Map** | `seed_map` / `mask_map` | `prediction_b[:, self.dim_coords + self.n_sigma:self.dim_coords + self.n_sigma + 1]` | Foreground probability map resembling the Euclidean Distance Transform (EDT). Peak values indicate instance centers. |

These three outputs are combined dynamically during instantiation in the `compute_crops` function (which calls `feature_engineering` to subtract center coordinates from spatial coordinates, dividing by $\sigma$) to yield the input features for the instance classifier.

### 4. Instance Segmentation (Instantiation) Algorithms
**Which functions perform the final instantiation (splitting predictions into individual instance masks)?**

The instantiation pipeline is defined in **`instanseg/utils/loss/instanseg_loss.py`** through the following functions:
* **`postprocessing(...)`**: The main entry point. It extracts predicted maps, identifies instance centers, crops candidate regions, runs the pixel classifier, and triggers prediction merging.
* **`torch_peak_local_max(...)`**: Finds local maxima on the `mask_map` (EDT/seedness map) using max-pooling non-maximum suppression to determine instance seeds.
* **`compute_crops(...)`**: Extracts local windows around seeds, applies `feature_engineering` (computing normalized relative offsets), and runs the `pixel_classifier` (MLP) to output local mask probabilities.
* **`merge_sparse_predictions(...)`**: Re-projects the cropped masks onto the full image using `convert`. It computes overlap IoUs with `fast_sparse_iou`, groups overlapping predictions with `find_connected_components`, merges them, and removes objects failing size (`min_size`) or confidence (`mean_threshold`) thresholds.

### 5. Deprecating Biological Metadata
**If we treat input images as ordinary images (no bio-markers/metadata), which files must be deleted or transformed?**

To strip biological specificity from the codebase:

1. **Delete completely:**
   - `instanseg/utils/biological_utils.py` (handles cell/nucleus boundary resolution, N-C ratios, and marker intensity plots).
2. **Transform (modify to remove biological dependencies):**
   - `instanseg/utils/loss/instanseg_loss.py`: Remove cell/nucleus boundary integration, `cells_and_nuclei` branching, and references to `biological_utils.py`.
   - `instanseg/utils/augmentations.py`: Delete hematoxylin/eosin stain simulation, Macenko normalization, `pseudo_brightfield` conversion, multiplexed `colourize`, and `pseudo_imc` noise modeling. Remove references to `markers_info`.
   - `instanseg/utils/augmentation_config.py`: Strip out predefined biological marker dictionaries (`markers_info`, `markers_info_gpt`) and tissue-specific augmentation modes.
   - `instanseg/inference_class.py`: Remove cell-nucleus boundary resolution steps and Rapids/Scanpy clustering of marker intensities.
   - `instanseg/scripts/train.py` & `instanseg/utils/model_loader.py`: Remove configs related to target segmentation channels (cell vs. nucleus), image modality assumptions, and pixel-size mapping.

### 6. Simplifying the Augmentation Pipeline
**Can we simplify the augmentation pipeline by replacing custom transformations with Albumentations or Torchvision?**

**Yes, absolutely.** The current pipeline manually implements transformations (such as flips, rotations, contrast adjustments, noise injection, and cropping) and synchronizes the random states between image and label channels (e.g., saving and setting RNG states via `torch.get_rng_state()`).

We can replace nearly all custom methods in `instanseg/utils/augmentations.py` with standard library calls:

* **Flips & Rotations:** Replace `flips(...)` and `rotate(...)` with `A.HorizontalFlip(p=0.5)`, `A.VerticalFlip(p=0.5)`, and `A.RandomRotate90(p=1.0)` in Albumentations.
* **Color and Contrast:** Replace `brightness_augment(...)` and `AdjustContrast(...)` with `A.ColorJitter(...)` or `A.RandomBrightnessContrast(...)`.
* **Gaussian Noise:** Replace `RandGaussianNoise(...)` with `A.GaussNoise(...)`.
* **JPEG Compression:** Replace `randomJPEGcompression(...)` with `A.ImageCompression(...)`.
* **Rescaling & Cropping:** Replace `torch_rescale(...)` with `A.Resize(...)`, `A.PadIfNeeded(...)`, and `A.RandomCrop(...)` (or Torchvision equivalents).

By defining a unified `A.Compose` pipeline, Albumentations will automatically apply identical spatial transforms to both the image and the mask simultaneously, eliminating custom random seed synchronization hacks.
